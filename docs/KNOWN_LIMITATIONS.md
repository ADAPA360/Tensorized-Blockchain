# Known Limitations - Tensorized Blockchain

This document lists the limitations of the current Tensorized Blockchain release stack.

## Testing Gaps
* **No Formal Test Suite**: This release does not include a formal test suite or tests directory. Testing is currently limited to basic CLI self-tests (`tb_cli.py run-self-tests`) and status checks.

## Dashboard UI
* **App Hardening in Progress**: The Streamlit application (`app.py`) is designed as an interactive demo cockpit and mission control. It is not hardened for long-running multi-user sessions, concurrent access, or production portal deployments. It degrades gracefully but should be treated as an experimental interface.

## Benchmarks
* **Preliminary Performance Estimates**: Benchmarks generated by `tb_benchmarks.py` are preliminary. Actual contraction speeds, rounding errors, and SVD latency will vary based on hardware acceleration, CPU core counts, and platform-specific NumPy/SciPy linear algebra bindings (such as MKL or OpenBLAS).

## Audit Status
* **Security Audit Pending**: The cryptographic signatures, block verification rules, serialization routines, and memory storage formats have not been reviewed by an external cybersecurity auditing firm. The codebase is research-grade and must not be used to secure real financial assets or critical industrial infrastructure.

## Consensus Robustness
* **Research-Grade Consensus**: The Proof-of-Coherence consensus protocol is a research concept. It has not been validated under Byzantine fault conditions, network partitioning, or adversarial sybil attacks. 

## Cognitive Lobe Scaling
* **Target Capacity vs Local Demo**: Large-scale lobe configuration (up to 2.5B parameter weights) is a governed capacity target for cluster deployment. The default local configuration runs small, lightweight NCP and CfC models suited for immediate local CPU execution and quick demonstration.
